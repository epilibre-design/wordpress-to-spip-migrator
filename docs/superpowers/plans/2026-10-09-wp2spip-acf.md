# wp2spip — sous-projet 9 : extension `wp2spip_acf` — plan de réalisation

**Goal:** Importer les champs ACF des articles et pages WordPress en champs extras de `spip_articles`, modifiables avec Champs Extras Interface, par une extension de wp2spip dans un dépôt séparé.

**Architecture:** Plugin SPIP `wp2spip_acf` (dépôt git local `wp2spip_acf`, branche `main`), sur le modèle de `wp2spip_yoast` : pipelines `wp2spip_traitements` (traitement `importer_acf` en dernier) et `wp2spip_plugins_requis` (Champs Extras et son interface), pipeline propre `wp2spip_acf_correspondances`. Fonctions pures dans `inc/wp2spip_acf.php` (groupes applicables, colonnes, saisies, conversion des valeurs, lecture des définitions et des valeurs), traitement dans `wp2spip/importer_acf.php`. Le dépôt de l'extension est la référence du code (ce plan ne le recopie pas).

**Tech Stack:** PHP (SPIP 4.4, Champs Extras 4.3, Champs Extras Interface 4.3, Saisies), PHPUnit 13 (classes de test de wp2spip installées en source par Composer), bash.

Spec : `docs/superpowers/specs/2026-10-09-wp2spip-acf-design.md`. Prérequis : sous-projets 5 à 8 réalisés.

## Global Constraints

- Messages de commit sans trailer ; ne jamais nommer le site WordPress réel dans les fichiers versionnés ni les commits.
- Tables WordPress nommées par `wp2spip_table()`.
- Dépôt de l'extension local seulement : aucun dépôt distant créé ni poussé.
